# 评审一个 PR

**本技能是指导，不是完整清单。** 先核实并拉取 PR 的活基线，再读 diff 与足够的周边代码去理解设计。把正确性、生命周期、安全与被破坏的必需行为排在风格之前；一条有据的阻塞点胜过长长一串吹毛求疵。

## 事实来源

- [`AGENTS.md`](../../../AGENTS.md)：常驻的通用工程约定。
- [`doc-standard.md`](../../references/doc-standard.md)：文档放置与文风纪律。
- [`prose-standard`](../prose-standard/SKILL.md)：注释、文档、提示词与可见字符串的覆盖要求与编辑判断。
- [`changes/README.md`](../../../.changes/README.md)：链的层数与格式；与一条链的分歧是一次设计讨论，不是自动否决。
- [`pre-push-checks`](../pre-push-checks/SKILL.md)：作者应当跑过的最小证据集。

## 阻塞性要求

1. **新增的 prose 要经过语义评审。** 用 [`prose-standard`](../prose-standard/SKILL.md) 逐段审每一处新增或改动的 Markdown、注释、提示词、描述、诊断与可见字符串；机械检查不能确立这些性质。
2. **文档与代码一致。** 配置、默认值、错误、字段与公开行为在同一次改动里更新对应文档与注释。注释陈述不显然的约定；实现叙述、测试走查、评审历史、重复的理由都要删掉或改为指向唯一归属处的链接。
3. **注册要能清理。** 每个新的注册项都要有对应的释放路径。
4. **必需证据存在。** 确认作者为本次 diff 跑过最窄的相关检查，且 CI 覆盖完整矩阵；评审两者都查不到的语义缺口。

## 人工检查

- **意图与接口约定**：追踪每一处改动接口的两端，确认实现与 PR 及任何链一致，包括错误、取消、所有权与释放。
- **生命周期与并发**：对异步初始化、回调、进程或拆除，检查发布前的竞争、await 期间的取消、独立的错误上报、回调隔离、重入前的所有权、以及彻底静止的释放。
- **范围、所有权与必要性**：把每个抽象、状态机、选项、防御性拷贝与兼容路径映射到它当前的约定、生产消费者与归属模块。质疑无关特性与投机式通用化。
- **配置与公开选择**：每个默认值、公开操作集、格式或引入的外部概念，都需要当前消费者证据或先例；证据不足时要求显式选择或推迟。
- **强制路径**：跟着每一条拒绝路径走到真正执行它的操作；检查能绕过 schema、提示词、外观层或监听顺序的直接与替代调用方。
- **边界覆盖到最终结果**：定位完整产出或保留结果的拥有者（含包装与元数据）；探测极小值与精确上限、超大单块与多字节文本。
- **真实入口路径**：测试在相关时应走真实的加载器、入口脚本、worker 或子进程；手工挂载的实例抓不到非法的导出错误。
- **测试强度**：断言要能在预期回归上失败，并验证外部状态、日志、事件或释放，而不是复述实现或信任某人的报告。覆盖率是必要条件，不是场景正确的证据。
- **链与 diff 一致**：对照最终 diff 核实 `plan.md` 的 `## Files`——列出的文件都改到了，改到的文件都列了；实现偏离计划时，`plan.md` 在同一次改动里更新。
- **链的层次**：改动若改变系统行为或越过既有策略边界，就该有 `spec.md`。闸门只强制 `spec ⇒ intent`，"该不该有"是判断，评审是唯一会拦的地方。
- **快照变化**：对外可见的改动要更新快照，或说明为什么没有快照适用。把期望输出的 diff 当作行为变化来审，而不是格式噪声。

## 报告发现

陈述缺陷、位置、影响与证据。局部缺陷贴在最紧的 diff 范围上；跨切面的架构或范围问题用 PR 级评论。把阻塞项与建议分开，省略已经由绿灯闸门强制的问题。使用已有的评审线程回复。收到评审意见时，逐条核实，凭技术理由修复或反驳，不做表演式认同。
