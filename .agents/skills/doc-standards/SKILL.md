# 应用文档标准

文档规则在 [`doc-standard.md`](../../references/doc-standard.md)。本工作流覆盖放置、语料审计、字数与校验，跨 Markdown、注释与文档字符串。它是指导，不是脚本；覆盖要求与编辑判断用 [`prose-standard`](../prose-standard/SKILL.md)，**永远不要仅凭长度判定缺陷**。

## 事实来源（去读，不要复述）

- [`doc-standard.md`](../../references/doc-standard.md)：分层、教程与参考形态、归属表、字数与 slop 清单。
- [`changes/README.md`](../../../.changes/README.md)：一条链何时需要哪一层、每层写什么、什么时候归档。
- 根 [`AGENTS.md`](../../../AGENTS.md)：本技能所守护的字数纪律背后的常驻军令。

## 先审结构，再审文字

对每份面向人的文档套用标准的写作顺序。**不要**把这一遍结构审查套在变更链上。

1. 定位文档在仓库与导航树里的位置，说明它自己的主题，并识别它的直接子级。
2. 确定允许的细节粒度：文档主题写全，直接子级按用途与高层行为概述，更深的解释下沉到拥有它的子级并链接。
3. 按**实际用途**而非路径或标题判定形态。教程必须是有序工作通往可观察结果；参考必须在明确范围内支持查阅，不要求顺序阅读。
4. 对教程，判定读者起点与每个概念的入门、进阶或高级；把过早的内容重排到前置之后，把可选的进阶细节移到后面的教程或参考。
5. 教程与参考都实质内容时拆分；其中一部分很小时放在显式标注的章节里。

再检查那些让放置变贵的约束：

- 移动是原子的：从旧位置删除、在新位置加入、并在同一次改动里修好所有入链。
- 生成的目录永不手改；若该事实属于那里，改生成器的源。
- 重命名或移动文档前，先 grep 入链。

## 审计语料

结构审查之后，用最省事的探针先找 slop 清单里的东西，再逐段做语义判断。

1. 度量：列出带字数登记的文档，并找出未登记的异常大文件。
2. 用 [`trim-cot-leakage`](../trim-cot-leakage/SKILL.md) 找推理过程泄漏：叙述的历史、只存在于设计过程的引用、评审编排、控制流叙述、测试走查。只保留不显然的约定或持久理由。
3. 用独特短语 grep 找重复。只留一个归属处，其余改为链接。
4. 用手写的目录、测试或状态清单、注释复述，替换为权威的树、脚本或生成参考。
5. 若删掉的不是解释而是**承诺过的行为**，先用一条 `intent.md`。

排除 `.changes/archive/`：那是冻结快照。活跃文字可以修好、重定向或删除一条指向它的入链，但不要顺着清理进到冻结目标内部。

保留每一条承重规则，最好是一到三行加一个指向理由的链接。删掉故事、重复、状态标注，以及用来推导出规则的那条路径。

## 字数超额时

套用 [`doc-standard.md`](../../references/doc-standard.md) 里的"搬迁、压缩、抬额"顺序；本技能只提供上面的工作流探针。

## 校验与 PR 卫生

至少跑 `python3 .agents/scripts/check_docs.py` 与 `git diff --check`；注释改动可能需要重生成相关目录。PR 描述里给出字数增减、解释任何有意超额的例外，并列出实际跑过的检查。
