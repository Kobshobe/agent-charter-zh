# 文档标准

本文件定义文档的分层、写作规则与字数控额，约束仓库根的 `*.md`、`docs/`、`.agents/`、`.changes/` 里的 markdown，源码树里的笔记闸门不扫。变更链（含示例链）同其他文档一样受一段一行与链接校验，只是不登记字数控额；[`.changes/`](../../.changes/README.md) 的冻结快照只校验目录形状。

## 一个事实只有一个家

每条事实都有唯一的归属层；在别处只保留链接。先决定一段内容属于哪一层，再落笔。

| 层 | 职责 | 不该放的东西 |
|---|---|---|
| 根 `AGENTS.md` | 常驻军令：agent 每次会话都需要在上下文里的规则，每条一到三行，链接到它所属的层 | 故事、完整示例、情境化流程、从链接处复述的内容 |
| 架构文档 | 有序的地图：组成、核心模块、数据流、扩展点；动核心代码前必读 | 类型定义、逐模块细节、决策理由、实现状态标注 |
| 子系统 / 模块参考 | 每个子系统一页：类型定义、语义、公开接口 | 行为叙述、决策理由 |
| 变更链（`.changes/`） | 一次改动的三层产物：问题、系统行为、这次怎么做；合并后冻结 | 当前行为的权威描述、后续改动的回填 |
| 事故复盘（postmortem） | 事故故事——唯一允许叙事的地方 | —— |
| Cookbook | 带编号验证步骤的操作指南 | 设计理由（链接到对应变更链） |
| 模块 README | 该模块的约定：配置、语义、限制、扩展点 | 注释复述、其他模块的关切 |
| 开发指南 | 环境搭建、日常流程、CI 概述 | 逐项检查清单（会与脚本漂移） |
| Skill（`.agents/skills/`） | 可复用工作流与判断标准 | 产品与运行时约定（属于文档或源码） |

放置原则：缺陷 → 复盘；这次为什么这么做 → 变更链；当前为什么是这样 → 架构文档或模块 README；步骤 → cookbook；类型定义 → 子系统参考；常驻规则 → 根 `AGENTS.md` 并链接理由。

## 教程还是参考

- **教程**：通往某个结果的有序路径，只引入每一步需要的东西。
- **参考**：定义一个查阅范围，陈述当前行为，不设教学顺序。

两者都实质内容时分开写；只有其中一部分很小时才在同一文档里显式标注。

写教程前先判定读者的起点知识，并把每个概念标为入门 / 进阶 / 高级；先建立前置，再讲依赖它的概念；难度递增；把不必要的进阶内容移到后面的教程或参考。

写作顺序：先定位文档在树中的位置 → 确定允许的细节粒度 → 选教程或参考 → （教程）按前置与难度排序 → 把属于下层的细节搬走 → 用链接指向它们的新位置。

## 写作规则

- **写当前状态，不写变更历史。** 不用"以前 / 现在 / 不再"，不提 PR 与提交；把变化故事留在变更链或复盘里。
- **一段一个物理行。** 用编辑器软换行；代码块、表格、列表结构保持原格式。
- **代码块必须可编译 / 可运行。** 文档里的示例代码要能被对应工具验证，否则不要放。
- **注释与文档陈述完整的约定，而不是推理过程。** 保留行为、失败、时序、所有权与安全使用的信息；删掉叙述、测试走查、评审分析、代码复述。
- **具体命名参与者与事实。** 写"响应字段""JSON 校验""导出接口"，而不是"响应形状""校验边界""模块形状"；`contract` / `boundary` 这类词只留给真正的约定与边界。
- **交叉引用用相对 markdown 链接**，不要裸文件名或编号；链接必须可达、锚点必须存在，由 [`.agents/scripts/check_docs.py`](../scripts/check_docs.py) 校验。

## 反 slop 清单

在任意文档里搜这些，见到就处理：

- 同一条规则出现在多个层。用一个独特短语 grep，只保留一处，其余改为链接。
- 叙述历史或故事："以前 / 现在 / 不再 / 曾经 / 改名 / 挪动"、PR、提交。
- 实现状态标注："已实现！""未来：…"。状态会腐烂，仓库结构与清单才是权威。
- 手工复述目录、注释、测试或模块清单——当源码或生成器是权威时。
- 推理过程：逐步实现叙述、显然分支的证明、测试走查、被否的局部方案。
- 在多个并列成员旁重复理由，而不是在拥有它的能力或辅助函数处写一次。
- 段落墙：一段塞进好几条规则与括号插入语。拆开或下沉。
- 强调通胀：到处加粗、大写、"关键的是"。把强调留给真正改变行为的子句。
- 变更链里的测试走查与实现叙述：链记的是问题、系统行为与执行计划，不是过程复盘。

## 字数控额

[`.agents/scripts/doc-budgets.json`](../scripts/doc-budgets.json) 登记各文档的字数上限；[`check_docs.py`](../scripts/check_docs.py) 在超出、贴住上限或漏登记时失败。

闸门变红时，按顺序处理：

1. **搬迁**：属于别层的内容搬过去，需要时留一行链接。
2. **压缩**：确实属于这里、但能更短的内容。
3. **抬额**：只有内容确实需要空间时才抬高上限，并在改动说明里解释这次登记表的差异。上限过低是配额 bug。

上限是护栏，不是缩减目标。命中的文档保持至少 5% 余量，闸门会判这一条；压不下来就抬高上限，并在改动说明里解释登记表的差异。
