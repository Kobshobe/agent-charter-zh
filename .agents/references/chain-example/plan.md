# Plan: 构建产物按内容哈希缓存

## Files

- `build/cache.py`（新增）：内容哈希、缓存键与命中判定。
- `build/pipeline.py`：每个构建步骤声明输入集，接上缓存查询。
- `build/tests/test_cache.py`（新增）：单元与集成测试。
- `docs/build.md`：缓存目录与 `BUILD_CACHE_DIR` 的约定。

## Order of work

1. 在 `pipeline.py` 里给每个步骤加输入集声明，先不启用缓存——此时行为不变。
2. 实现 `cache.py` 的哈希与命中判定，只对已声明输入集的步骤生效。
3. 打开缓存，跑全量测试。
4. 更新 `docs/build.md`。

## Risks

- 漏声明输入集会让某个步骤永远不命中，表现为"仍然慢"，而不是"产出错误产物"——这是有意的故障方向。
- 缓存目录增长需要清理入口，这是新增的运维项。

## Proof

- 单测：相同输入集产出相同缓存键；改动任一被声明输入会改变缓存键；未声明输入的步骤不进入缓存。
- 集成测试：两次相同输入的连续构建，第二次命中缓存且产物与第一次逐字节相同。
- 实测：连续提交的构建时间从约 9 分钟降到约 2 分钟。
